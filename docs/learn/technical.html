0Stack and deployment

The root package manifest declares Expo 57, React Native 0.86, React 19 and TypeScript. The server compiles TypeScript and uses node:http, SQLite or pg, AWS S3/Cognito integrations, aws-jwt-verify, web-push and ffmpeg. Feature folders are internal modules, not separate microservices.

The diagram combines configured hosted boundaries, not verified release status. Default Compose runs nginx plus one Node application container. PostgreSQL and S3 are external; local runs use SQLite and disk. Hosted-dev names retain demo after the synthetic Demo's removal.

1HTTP and proxy trust

http.ts dispatches routes using paths and regular expressions. nginx proxies /api/* to Node with that prefix removed, keeps API responses out of caches, and disables proxy buffering for SSE. Auth transport and browser origin validation precede session/resource checks.

authTransportIsSecure accepts socket TLS, an explicitly enabled loopback exception, or matching X-Rewind-Origin-Auth and X-Forwarded-Proto: https. CloudFront enforces viewer HTTPS and supplies the origin proof; nginx forwards it and sets the protocol. A forwarded protocol header alone does not authenticate the proxy. The origin hop is HTTP. The loopback exception requires a loopback peer/host and no forwarded protocol header.

Intake defaults are 30 seconds idle, 120 seconds total upload, two concurrent intakes and one processing request; selectors live in config.ts. Process-local limits are not a distributed rate limiter.

2Managed login and opaque sessions

The callback checks state/replay, nonce, ID-token claims and verified email, then maps cognito_sub to the account. The API accepts the Rewind session, not a Cognito token. The cookie is __Host-rewind_session, Secure, HttpOnly, SameSite=Lax, Path=/ and no Domain. Idle expiry slides for seven days, bounded by 30 days absolute. The persisted credential is a SHA-256 token hash.

Developer password sign-in remains local/dev under REWIND_AUTH_PASSWORD; browser responses keep the token in the cookie, while native responses return a bearer token for SecureStore. Different simultaneous cookie/bearer credentials fail. Release refuses password sign-in; native clients do not show managed login. See the session contract and existing Cognito decision note.

3SQLite and hosted PostgreSQL

REWIND_DATABASE_URL selects PostgreSQL; otherwise db.ts opens SQLite under REWIND_DATA_DIR. SQLite uses WAL, foreign keys and a busy timeout. The PostgreSQL bridge presents the synchronous prepare/run/get/all/exec surface through a pg worker thread; calling SQL blocks the caller. This is not an asynchronous persistence rewrite.

PostgreSQL uses advisory locks for serialized writers, savepoints for compatible failure behavior, translated SQL and matching migrations. Runtime verifies remote TLS with the bundled RDS CA and binds the database to its environment. TLS disable is loopback-only. Read ADR-0003 for the decision and historical measurements.

At the baseline, database.tf enables dev cutover but disables release provisioning/cutover. That declaration is not a current health check. Release persistence/recovery remains #504; operations stay in the database runbook.

4Internal loops and durable work

cli.ts start runs HTTP and the cycle scheduler, plus the reminder loop when providers are configured. The scheduler calls runWorkerTick for real groups. Optional worker CLI mode runs the same job machinery separately; default Compose has no standalone worker service. The PostgreSQL I/O thread is a different mechanism.

Clip and film jobs persist in SQL. Claims have leases and claim_generation fences; progress/completion must match the claim, preventing stale workers from overwriting newer work. ffmpeg runs as a child process with argument arrays. Retry limits and typed failure categories live in worker.ts and the job processors. These are durable database jobs, not an external message broker.

5Storage and media capabilities

Configuration Representation / intake Boundary
disk No configured MediaStore; staged/processed filesystem paths; authenticated byte intake through Node. Local product path.
local Legacy immutable object-store adapter; not the disk intake path. Retained; do not extend.
s3 Immutable object refs and a signed incoming PUT transport. Hosted path; scope binds environment/group, exact key/version, digest, length, type and expiry.

MediaStore defines put/head/read/delete for the local/S3 object adapters. Configured runtime wiring shares the selected store across HTTP, jobs and lifecycle. S3 finalization checks version, checksum, size and encryption before trusting incoming media. A signed upload URL does not grant playback or publish permission.

The active media root uses SSE-S3 (AES256), versioning and public-access blocking. The adapter supports SSE-KMS when configured with a canonical key ARN, and the separate private-media module requires it. Compose does not pass a KMS selector. Do not describe the current root as KMS.

Direct S3 PUT avoids Node's intake hop. Node still materializes/verifies S3 bytes for processing and authorized playback/download, then writes outputs to S3. Media therefore still passes through Node.

Read capabilities are two-minute opaque URLs backed by a process-local grant. They may work without a cookie, but resolution rechecks the bound session, accepted/selected membership, published cycle and exact verified output; a different presented session is rejected. They expose neither the application session token nor a raw S3 URL.

6Realtime

Chat and cycle events use SSE. Persisted events support replay; the in-memory hub distributes events after commit. The hub is process-local, so a second API replica would require coordination for live delivery. nginx disables buffering; a database shared between replicas does not by itself share the hub.

7Client runtime

App.tsx supplies RealAccountProvider; real-account screens use HTTP clients and domain contracts, with platform capture/file/token adapters. EXPO_PUBLIC_LOCAL_BASE_URL is bundled at build time (hosted web uses /api). A missing URL makes sign-in unavailable; it does not enable an offline Demo. EXPO_PUBLIC_* settings are public, never a place for server secrets.

8PWA and web-only reminders

The service worker keeps API/media/non-GET traffic network-only, uses a network-first navigation shell and caches build assets. It does not provide an offline private-media queue. A stamped build invalidates old shell caches.

The reminder outbox persists intended delivery and retry state; configured web-push providers use VAPID. Provider acceptance does not establish visible notification receipt, and no exactly-once device-delivery guarantee is claimed. iPhone delivery uses an installed Home Screen PWA over HTTPS. Expo/native push remains disabled and is outside this work.

9Build and delivery

Expo exports the web bundle; TypeScript builds the Node runtime. Compose runs read-only containers with explicit data/media mounts. CloudFront/nginx expose the app and same-origin API. The dev workflow requires Quality for its selected revision; a dev merge triggers deployment. Release promotion follows protected main and release-environment rules. Workflow configuration is distinct from deployed health and acceptance.

Procedures remain in deployment guidance. This guide performed no AWS action and establishes no new release result.

10Verification boundaries

npm run test:fast builds the server once, then runs root, server and frontend suites concurrently. PostgreSQL has a separate server-suite path. Focused tests diagnose one file. Slow, coverage and accessibility checks apply to web export, routing, PWA, accessibility changes and release promotion under the working agreement.

For this documentation change, format/source/link checks and rendered learning-page inspection validate the documentation. They do not replace application tests, real-provider acceptance or iPhone notification receipt.

Known architectural limits

  • Process-local SSE, capabilities, caches and Cognito replay tracking prevent assuming transparent multi-replica operation.
  • The synchronous PostgreSQL bridge blocks the calling thread; serialized writes preserve parity rather than exploiting full PostgreSQL concurrency.
  • ffmpeg and API work share host resources. Concurrency limits bound work but do not prove capacity under arbitrary load.
  • Release operational acceptance and current device integration results belong to their tracking issues, not this source map.
