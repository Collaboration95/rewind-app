L1What the app does

  • A friend group runs cycles. Everyone drops short clips/photos during the cycle.
  • Nobody sees anything until the cycle ends. Then the clips are stitched into one film and revealed together (the "premiere").
  • Films pile up in the Archive. There's group chat on the side, plus web-push reminders.
  • Quota (glossary): 5 contributions / 30 seconds per member per cycle.

Two modes exist: the real-account app (the product) and a synthetic Demo (frozen: kept only for tests/local runs, git tag demo-frozen-20261004). Many routes/files come in "demo" and "real" pairs, which is why the code looks doubled.

L2The boxes (hosted dev)

  • One server process does everything: API, chat stream, video jobs, schedulers. Monolith by design (the course brief recommends it).
  • nginx serves the built web app and forwards /api/* to the Node runtime. CloudFront's secret header proves requests came via HTTPS.
  • DB = node:sqlite (built into Node 22), a single file. 28+ numbered SQL migrations in server/migrations.
  • Media: disk locally, s3 hosted (private bucket, KMS, Terraform-managed).
  • Container is hardened: read-only FS, all capabilities dropped, 768 MB cap.

L3Life of one clip

  • Intents bind bytes + checksum + version, so the client can't upload something other than what was approved.
  • Queue kinds are just clip and film; statuses pending / processing / failed. It's a table, not Redis/SQS (inferred: no broker in deps).
  • Locked state: until reveal, the server returns metadata only; media access goes through an authorised /media/access/… route.

L4Code map

  • Ports & adapters on the client: UI talks to repository interfaces; Demo and Runtime each implement them (ADR-0001).
  • npm run architecture:check enforces it: src/domain and cycles/engine.ts may only import relative files (no Expo, no SQLite).
  • Cycle engine takes an injected clock, so tests never wait on real time.
  • Big files to know: server/src/http.ts (4.5k), db.ts (2.2k), jobs/index.ts (2.1k). Everything routes through these.

L5From PR to running server

  • Only a commit that passed Quality can deploy. The new release is activated only if runtime + web health checks pass; otherwise the previous release is restored.
  • No static AWS keys in CI: GitHub's OIDC token is trusted by a deploy role scoped to the dev environment.
  • Terraform modules: private-media (S3+KMS), environment-identity; roots: demo (the live one), dev, prod (reserved, not initialised yet).
  • Docs say there are no routine application DB backups in the dev/prod plan (accepted lifecycle). Worth knowing for a SQLite-on-one-disk setup.
