Who owns what

Four placeholder members each own use-case models and at least one design problem, with Member C covering both cycle and Archive.

Member A, Member B, Member C and Member D are placeholders for names the team will fill in. This is the agreed presentation and study allocation, not a claim about historical authorship, effort or commit ownership.

The course requires each member to explain at least one use case at both analysis and design levels and at least one problem solved using a pattern. Prepare the analysis class view, an analysis sequence for each major flow, the design class view and the matching design sequences. For the design problem, prepare the brute-force alternative, candidates, choice, before/after class and sequence views, and implementation decisions.

The suggested two-minute outlines below introduce each member’s part; they do not replace the full use-case discussion or demonstration. ACCESS belongs to A, CAPTURE to B, CYCLE and ARCHIVE to C, and PARTICIPATION to D.

Questions to expect

Why not authorise using memberId from the request?
The client can change it. The server derives identity from the session and resolves the account’s group membership/profile.
How does Cognito differ from group authorisation?
Cognito establishes who signed in. Rewind decides which groups and owner operations that account may access.
How do you stop an invitation being used twice?
Acceptance rechecks persisted invite state inside the membership transaction and records acceptance with the resulting membership.
What changed from your older design diagram?
The Demo identity family was removed and Cognito was implemented. The current design converges sign-in into Rewind sessions and keeps explicit real-account membership checks.

Questions to expect

Who stops two simultaneous uploads exceeding allowance?
The server’s atomic count/duration reservation, not the screen’s displayed remaining count.
What if the user retries after the response disappears?
Reuse the idempotency key and reconcile the existing contribution rather than consuming another allowance.
Is the retro look always done on the phone?
The web photo path does it locally; web video does when re-encoding is supported. Otherwise the server applies the look. A processed flag avoids double grading.
Where is Template Method implemented?
It is not implemented as a base class with overridden steps. Capture uses Adapter contracts, sessions and hooks.

Questions to expect

How can the next cycle collect while the previous film is still compiling?
Closing the old cycle and creating/selecting its successor are transactional lifecycle work. Compilation is a separate durable job, so a slow film does not keep intake on the old cycle.
Why does a retry not let the old worker win?
The current persisted claim generation must match at finalisation. A stale worker cannot overwrite a later claim.
Why does the premiere last from publication rather than cycle end?
Compilation may finish late. release_published_at starts the configured 24-hour premiere after verified output is actually published.
What happens after a media capability expires or the process restarts?
The client refreshes authorisation and requests a fresh grant. Durable media remains stored; serving still checks session, membership, release and exact output identity.

Questions to expect

Why persist messages before publishing?
A live event must correspond to a committed message. If the connection drops, the client can recover the committed message from event replay.
How do you avoid a gap while replay meets live traffic?
Subscribe and buffer while taking a watermark, replay persisted message events through it, then flush newer buffered events once.
How does opting out affect pending work?
Preference and destination eligibility are rechecked; disabling a destination increments its generation so stale queued work cannot use that destination.
Does the reminder scheduler now recur automatically?
The runtime starts a bounded recurring loop when providers are configured. This proves the mechanism exists, not that a particular device displayed a notification.
