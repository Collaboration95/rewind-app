# Sprint 0 accessibility checklist

Use this checklist for every UI change and link the completed notes from the
issue evidence. It is a verification aid, not a claim that a screenshot proves
accessibility.

- [ ] Every interactive control has a clear accessible name.
- [ ] The screen has one clear accessible title or heading.
- [ ] Selected, focused, disabled, unavailable, and error states are conveyed
      by text or semantics as well as visual styling.
- [ ] Keyboard/focus order is usable on the supported web path; focus is
      visible and does not become trapped.
- [ ] Text remains readable when browser/system text is enlarged.
- [ ] Colour contrast is checked for body text, controls, focus, and status
      text; colour is not the only state signal.
- [ ] Loading, empty, retry, denied, and locked-safe states have understandable
      copy where the changed flow can reach them.
- [ ] No local-demo copy implies authentication, secure account ownership, or
      privacy that the implementation does not provide.

Record the browser/OS, viewport, assistive technology or keyboard method, and
known limitations in the issue evidence.
